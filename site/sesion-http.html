Una sesión HTTP típica

Traducción al español por Eduardo Chacon.
Original: «A typical HTTP session», de MDN Web Docs (Mozilla). Autores: colaboradores de MDN.
Licencia: CC BY-SA 2.5. Esta traducción se distribuye bajo la misma licencia. Los ejemplos de código se mantienen como en el original.

En los protocolos cliente-servidor, como HTTP, las sesiones constan de tres fases:

  1. El cliente establece una conexión TCP (o la conexión correspondiente si la capa de transporte no es TCP).
  2. El cliente envía su solicitud y espera la respuesta.
  3. El servidor procesa la solicitud y devuelve su respuesta, con un código de estado y los datos correspondientes.

A partir de HTTP/1.1, la conexión ya no se cierra después de completar la tercera fase, y el cliente puede hacer otra solicitud: esto significa que la segunda y la tercera fase pueden repetirse cualquier número de veces.

Establecer una conexión

En los protocolos cliente-servidor, es el cliente quien establece la conexión. Abrir una conexión en HTTP significa iniciar una conexión en la capa de transporte subyacente, que normalmente es TCP.

Con TCP, el puerto predeterminado de un servidor HTTP en una computadora es el puerto 80. También se pueden usar otros puertos, como 8000 u 8080. La URL de la página que se quiere obtener contiene tanto el nombre de dominio como el número de puerto, aunque este último puede omitirse si es 80. Consulta la referencia de URL para más detalles.

Nota: el modelo cliente-servidor no permite que el servidor envíe datos al cliente sin una solicitud explícita. Sin embargo, varias API web hacen posible este caso de uso, entre ellas la API Push, los eventos enviados por el servidor (server-sent events) y la API de WebSockets.

Enviar una solicitud del cliente

Una vez establecida la conexión, el agente de usuario puede enviar la solicitud (un agente de usuario suele ser un navegador web, pero puede ser cualquier otra cosa, por ejemplo un rastreador o crawler). Una solicitud del cliente consiste en directivas de texto, separadas por CRLF (retorno de carro seguido de salto de línea), divididas en tres bloques:

  1. La primera línea contiene un método de solicitud seguido de sus parámetros:
    • la ruta del documento, como URL absoluta sin el protocolo ni el nombre de dominio
    • la versión del protocolo HTTP
  2. Las líneas siguientes representan una cabecera HTTP, que le da al servidor información sobre qué tipo de datos es apropiado (por ejemplo, qué idioma o qué tipos MIME) u otros datos que modifican su comportamiento (por ejemplo, no enviar una respuesta si ya está en caché). Estas cabeceras HTTP forman un bloque que termina con una línea vacía.
  3. El último bloque es un bloque de datos opcional, que puede contener más datos y se usa principalmente con el método POST.

Ejemplos de solicitudes

Obtener la página raíz de developer.mozilla.org (https://developer.mozilla.org/) e indicarle al servidor que el agente de usuario preferiría la página en francés, si es posible:

GET / HTTP/1.1
Host: developer.mozilla.org
Accept-Language: fr

Observa esa última línea vacía: separa el bloque de datos del bloque de cabeceras. Como no se indica ninguna cabecera HTTP Content-Length, este bloque de datos se presenta vacío y marca el final de las cabeceras, lo que permite al servidor procesar la solicitud en cuanto recibe esa línea vacía.

Por ejemplo, para enviar el resultado de un formulario:

POST /contact_form.php HTTP/1.1
Host: developer.mozilla.org
Content-Length: 64
Content-Type: application/x-www-form-urlencoded

name=Joe%20User&request=Send%20me%20one%20of%20your%20catalogue

Métodos de solicitud

HTTP define un conjunto de métodos de solicitud que indican la acción que se desea realizar sobre un recurso. Aunque también pueden ser sustantivos, a estos métodos a veces se les llama verbos HTTP. Las solicitudes más comunes son GET y POST:

  • El método GET solicita una representación de los datos del recurso indicado. Las solicitudes que usan GET solo deben obtener datos.
  • El método POST envía datos a un servidor para que pueda cambiar su estado. Es el método que se usa con frecuencia en los formularios HTML.

Estructura de la respuesta del servidor

Después de que el agente conectado envía su solicitud, el servidor web la procesa y, finalmente, devuelve una respuesta. Al igual que una solicitud del cliente, la respuesta del servidor está formada por directivas de texto separadas por CRLF, aunque divididas en tres bloques:

  1. La primera línea, la línea de estado, consiste en la confirmación de la versión de HTTP usada, seguida de un código de estado de la respuesta (y su significado breve en texto legible para las personas).
  2. Las líneas siguientes representan cabeceras HTTP específicas, que le dan al cliente información sobre los datos enviados (por ejemplo, el tipo, el tamaño, el algoritmo de compresión usado o indicaciones sobre el almacenamiento en caché). Igual que en la solicitud del cliente, estas cabeceras HTTP forman un bloque que termina con una línea vacía.
  3. El último bloque es un bloque de datos, que contiene los datos opcionales.

Códigos de estado de respuesta

Los códigos de estado de respuesta HTTP indican si una solicitud HTTP concreta se completó correctamente. Las respuestas se agrupan en cinco clases: respuestas informativas, respuestas exitosas, redirecciones, errores del cliente y errores del servidor.

  • 200: OK. La solicitud se realizó correctamente.
  • 301: Moved Permanently. Este código de respuesta significa que la URI del recurso solicitado cambió.
  • 404: Not Found. El servidor no encuentra el recurso solicitado.
